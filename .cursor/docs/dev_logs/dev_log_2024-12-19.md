## Auxiliary Heads System Implementation

### Overview
Implemented a comprehensive auxiliary heads system for the hyperencoder project to enable multi-task learning on MIDI metadata. This feature allows the model to learn semantic representations of musical structure by predicting musical properties from latent representations.

### Technical Implementation

#### Core Modules Created

1. **`hyperencoder/modules/auxiliary_heads.py`**
   - `AuxiliaryHeadConfig`: Pydantic configuration class with complete validation
   - `AuxiliaryHead`: Neural network module supporting regression, classification, and multi-label prediction
   - Configurable architecture with hidden layers, activation functions, and dropout
   - Target preprocessing including normalization and log transforms
   - Automatic output dimension calculation based on head type

2. **`hyperencoder/modules/auxiliary_losses.py`**
   - `AuxiliaryLoss`: Integrates with `stable_audio_tools.training.losses.MultiLoss`
   - `FocalLoss`: Handles class imbalance in classification tasks
   - `MultilabelFocalLoss`: Focal loss for multi-label classification
   - Robust error handling with graceful degradation

#### Configuration System Updates

3. **`hyperencoder/datamodels/model_config.py`**
   - Added `AuxiliaryHeadsConfig` class with comprehensive validation
   - Integrated into `ModelConfig` with proper defaults
   - Validates unique head names and target keys
   - Includes logging and validation control settings

#### Training Integration

4. **`hyperencoder/training/hyperencoder.py`**
   - Updated `HyperEncoderTrainingWrapper` to support auxiliary heads
   - Added `_setup_auxiliary_heads()` method for initialization
   - Implemented `_evaluate_auxiliary_heads()` for validation metrics
   - Fixed critical bug where batch metadata was being discarded
   - Added auxiliary heads config parameter to factory functions

#### Configuration Presets

5. **`configs/auxiliary_heads/basic_song_level.yaml`**
   - Comprehensive configuration with 7 auxiliary heads
   - Covers tempo, duration, velocity, note density, time signature, key signature, and track count
   - Balanced loss weights and appropriate target ranges

6. **`configs/auxiliary_heads/tempo_velocity.yaml`**
   - Minimal configuration for testing and lightweight training
   - Focuses on tempo and velocity prediction only
   - Smaller network architectures for faster training

### Key Technical Decisions

#### Architecture Choices
- **Input Processing**: Auxiliary heads process `inner_latents` (post-encoder, pre-decoder)
- **Independence**: Each head is completely independent with no shared layers
- **Integration**: Seamless integration with existing `MultiLoss` system
- **Error Handling**: Graceful degradation when MIDI metadata is missing

#### Supported Head Types
- **Regression**: Continuous values (tempo, duration, velocity, note density)
- **Classification**: Discrete categories (time signature, key signature, track count)
- **Multi-Label**: Multiple categories (instrument programs)

#### Loss Functions
- **Regression**: MSE, MAE, Huber, Smooth L1
- **Classification**: CrossEntropy, Focal Loss, NLL
- **Multi-Label**: Binary Cross-Entropy, Multilabel Focal Loss

#### Validation Metrics
- **Regression**: MAE, MSE, denormalized metrics for interpretability
- **Classification**: Accuracy
- **Multi-Label**: F1 score, precision, recall

### Bug Fixes

#### Critical Training Bug
- **Issue**: Batch metadata was being discarded in training step (`outer_latents, _ = batch`)
- **Impact**: Auxiliary losses couldn't access MIDI metadata, causing silent failures
- **Solution**: Updated both training and validation steps to preserve metadata
- **Fix**: Changed to `outer_latents, info = batch` and added `"info": info` to `loss_info`
